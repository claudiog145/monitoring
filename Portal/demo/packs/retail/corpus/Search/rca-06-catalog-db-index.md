# Root Cause Analysis - Catalog database slow item detail after index drop

**Date:** 2026-01-20
**Company:** Mercado Libre (demo) - synthetic document, every name and number is invented
**Demo scenario:** `search-latency-mlm` (latency on the discovery journey)
**Services:** search-api (`GET /api/items`), storefront (`GET /item`)
**Partner:** catalog-db (`catalog-db.retail.internal`, `SELECT item_detail`)
**Severity:** SEV-3 - duration 47 minutes

## Bottom Line Up Front
A schema migration dropped and recreated an index on the item variations table. While it rebuilt, `SELECT item_detail` scanned the table and `GET /api/items` P95 rose from 170 ms to 1.9 s on every site. The storefront item page (`GET /item`) followed and some requests were canceled after 3000 ms.

## What Happened
- 11:02 UTC - Latency P95 of `search` (domain grain) breaches on step item-detail.
- 11:05 UTC - Storefront item-page latency rises; TaskCanceledException in `ItemPage.LoadItem`.
- 11:30 UTC - DBA identifies the running index rebuild from the 11:00 migration.
- 11:49 UTC - Rebuild completes; latency normal.

## 5 Whys
1. Why was item detail slow? Because `SELECT item_detail` did a full scan.
2. Why a full scan? Because the covering index was being rebuilt.
3. Why rebuild in business hours? Because the migration tool ran DROP/CREATE instead of an online rebuild.
4. Why DROP/CREATE? Because the migration was generated by an ORM default.
5. Why was it not reviewed? Because migrations on catalog-db had no DBA review step.

## Corrective Actions
- Online index operations only on catalog-db.
- DBA review required for catalog-db migrations.
