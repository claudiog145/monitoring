# WHAT THIS FILE IS
#   Every line below is a company-specific literal that is still hardcoded in
#   JourneyMonitor.Core or JourneyMonitor.Infrastructure. The guardrail fails on any such
#   literal that is NOT listed here, so this file is the exact, countable boundary between
#   "debt we already owe" and "debt someone just added".
#
# THIS LIST IS MEANT TO SHRINK, NEVER TO GROW.
#   Each entry is a blocker for onboarding a second customer. When the value moves into
#   CompanyProfile, DELETE the line - the guardrail fails on stale entries precisely so the
#   count cannot drift away from reality. The number of lines here is the progress metric.
#
# ADDING AN ENTRY
#   Requires a real reason in the third column (the test rejects reasons under 10 characters).
#   "temporary", "wip" and "fix later" are not reasons. If you cannot explain in one line why
#   this literal cannot live in the company profile today, it belongs in the company profile.
#
# FORMAT
#   path|literal|reason
#     path    - relative to Portal/src, forward slashes. Line numbers are deliberately NOT
#               part of the key: they churn on every edit and would make this file unmergeable.
#     literal - the rule id from CouplingInventoryTests.Rules (not the matched text).
#     reason  - why it is still here, and ideally who owns moving it.
#   Lines starting with '#' and blank lines are ignored.
#
# EXEMPT LOCATIONS (never need an entry)
#   - JourneyMonitor.Core/Company/**           the profile model itself
#   - any file whose name contains "Arrivia"   the per-customer adapter/seed
#   - JourneyMonitor.Infrastructure/Kql/*.txt  raw KQL, migrated by a separate track
#
# WHAT IS *NOT* ENFORCED, AND WHY (read before arguing the count is too low)
#   - Comment-only lines. "Arrivia maps Service to Vertical" is documentation, not coupling.
#   - Company-flavoured IDENTIFIERS: the `Vertical` property (143 occurrences across 34 files,
#     including the SQL column and the Dapper row records), the `Club`/`Brand` nouns, and
#     `Domain` as a synonym for vertical. These are a mechanical rename owned by another
#     track; enforcing them here would bury the ~70 behavioural couplings below - the ones
#     that actually produce wrong answers for a second customer - under 150 cosmetic hits.
#     `IcePartnerId` IS enforced because it encodes a customer-identity concept, not a name.
#   - Genuine false positives that were checked and dismissed:
#       Infrastructure/Search/AzureDevOpsSearchTransport.cs:21 "499b84ac-...": the well-known
#         Azure DevOps AAD resource id, identical for every tenant - not a subscription.
#       Core/Incidents/IncidentIngestionPlanner.cs:236 and Infrastructure/Sql/SqlIncidentReader.cs
#         "00000000-0000-0000-0000-000000000000": the empty-GUID sentinel.
#       Core/Options/AzureDevOpsSearchOptions.cs:22 "arrivia": appears only in a doc comment
